# soccer-cards-app

サッカートレカ所持リスト PWA。iPhone Safari（ホーム画面に追加）で使う前提。
データは private リポジトリ [soccer-cards-data](https://github.com/tetsuf0605-rgb/soccer-cards-data) に置き、
GitHub Contents API で読み書きする。仕様の正はそちらの `docs/` にある4点。

## 技術方針

ビルドなしの静的構成。HTML + CSS + JavaScript（ES modules）のみで、
フレームワーク・npm依存・ビルドステップは使わない（push＝デプロイを維持するため）。

## 実機（iPhone）での確認

GitHub Pagesの公開からホーム画面追加、本番PATでの読み書きまでの手順は
[docs/iPhone実機確認手順.md](docs/iPhone実機確認手順.md) にまとめてある。

## ローカルでの動作確認

ES modules と Service Worker は `file://` では動かないので、必ずHTTPで配信する。

```sh
cd soccer-cards-app
python -m http.server 8765
```

- アプリ: <http://localhost:8765/>
- セルフテスト: <http://localhost:8765/dev/selftest.html>

### アイコン

`dev/icon-source.png`（正方形の元画像）から4枚を作る。

```powershell
powershell -ExecutionPolicy Bypass -File dev/gen_icons.ps1
```

| ファイル | 用途 | 作り方 |
|---|---|---|
| `icon-192.png` / `icon-512.png` | manifest の `purpose: any`、ブラウザのタブ | 元画像をそのまま縮小 |
| `apple-touch-icon-180.png` | iOSのホーム画面 | 同上。iOS側が角丸マスクをかけるが、金の枠は内側に十分入っているので切れない |
| `icon-512-maskable.png` | manifest の `purpose: maskable` | 内側70%に収め、地色を全面に敷く（円・角丸・しずく、どのマスクでも欠けない） |

差し替えたら **`sw.js` の `CACHE_NAME` を1つ上げる**（古い殻のキャッシュを掴ませないため）。
iOSのホーム画面に追加済みのアイコンは自動では変わらないので、一度削除して追加し直す。

### 設計上の約束ごと

- **書き込むのは `collection.json` と `targets.json` だけ**（v1.4）。
  `prices.json` / `players_info.json` は cowork、`teams.json` / `checklists/` / `gb/` は
  PC（Claude Code）が所有するので、書き込む関数を作らない（保存同期方式仕様 §2・§4）。
  `github.js` の `WRITABLE_PATHS` がPUTの入口で弾く
- **参照データが無くても止まらない。** `teams.json` / `targets.json` / `checklists/` / `gb/` の
  404 は「空」として扱い、絞り込み・テーマが効かなくなるだけにする（保存同期方式仕様 §4）
- **base64変換は必ずUTF-8バイト列を経由する。** 選手名や備考に日本語が入るため
  `btoa(JSON.stringify(...))` は使えない（`js/base64.js`）
- **Service Workerは同一オリジンのみ扱う。** GitHub APIのレスポンスはSWを通さない
  ＝PATで認証した個人データをキャッシュに残さない
- **`window.confirm` / `alert` は使わない**（`js/confirm.js` の画面内パネルで代用）。
  ホーム画面に追加したPWAやアプリ内ブラウザではダイアログが出ずに即 false が返ることがあり、
  「削除ボタンが効かない」「取り込みを中止できない」という詰まり方をする
- **Service Workerはネットワーク優先。** 古いアプリ殻を掴んで更新が届かなくなる事故を避ける
- **書き出しの体裁はスキーマ仕様§3のサンプルに合わせる**（`js/serialize.js`）。
  コミット履歴が台帳を兼ねるので、1枚追加した差分がそのカードの1ブロックで収まる形にする
- **書き込みは「このセッションでGETできた」ときだけ許す。** キャッシュのshaでPUTすると
  他端末の更新を巻き戻しかねないため、オフライン時は閲覧とエクスポートに限る

## セルフテスト

PATなしで検証できる範囲を `dev/selftest.html` にまとめている（GitHubへの実通信はしない）。
Contents API のレスポンスは `dev/fixtures.js` で差し替える。

`dev/fixtures.js` はスキーマ仕様 §3 のサンプル（架空の2枚）を Python で base64 化したもの。
アプリ側の符号器とは独立しているので、UTF-8経路の突き合わせに使える。再生成は:

```sh
python dev/gen_fixtures.py            # 既定で ../soccer-cards-data を読む
```

> **このリポジトリは public。実際の所持カードデータを `dev/` に焼き込まないこと。**
> `gen_fixtures.py` はサンプル以外を検出したら中止する。

### フェーズ1で入ったもの

- **オーバーレイマージ**（`js/merge.js`）— エントリがあればオーバーレイ優先。
  フィールド単位で存在を見るので、部分的なオーバーレイでも台帳側を巻き込まない。
  結果はスキーマv1.2の形を保つ（フェーズ4のエクスポートでそのまま使える）
- **8項目ソート**（`js/query.js`）— スキーマ仕様 §1 の対応表どおり。
  選手側のキーは playerId で結合して引く。値なしは昇順・降順どちらでも末尾。
  引退状況は文字列順ではなく 現役 → 引退 → 不明
- **検索** — 選手名（name / nameEn）。NFKCで全角を吸収し、
  ひらがなをカタカナに寄せる（かな入力で「べりんがむ」→「ベリンガム」に当たる）
- **詳細ビュー** — 全フィールドと価格履歴。オーバーレイ由来の値には出所を明記する

### フェーズ2で入ったもの

右上の「＋」から。判定JSONを貼り付け → 1枚ずつ確認 → 1枚ずつ保存（1枚＝1コミット）。

- **取り込みの読み取り**（`js/ingest.js`）— 写真判定運用仕様§4のJSON。単体・複数どちらも
  `items` で受ける。```json のコードブロックごと貼っても読める
- **選手マッチ** — nameEn（無ければカナ名）で既存選手を検索。大文字小文字・空白・
  アクセント記号・区切り記号のゆらぎを吸収する。完全一致が1人だけならそれを既定選択、
  それ以外は「新規作成」を既定にして、判定結果を初期値にした入力欄を開く。
  候補に出ない選手は検索欄から選べる
- **表記寄せ** — メーカー / シリーズ / バリエーション / プリント時チーム / シーズン /
  バインダー名 / 国籍を、既存の登録値から datalist で提示する
- **needsCheck の強調** — 判定側が自信なしと言った項目を色つきで囲み「要確認」を付ける
- **シリアルの最終確認** — 値が入っているときは「実物と一致」チェックなしでは保存できない
  （空欄のときは不要。まとめ撮りのギャラリー層は serial が null で返る前提のため）
- **保存**（`js/github.js`）— collection.json だけをPUT。409（sha不一致）なら
  再GET → 同じ変更を当て直し → 再PUT を自動で1回。IDの採番は当て直しの中でやり直すので、
  他端末が先に登録していてもIDは衝突しない
- **自動で付ける値** — カードID `c-YYYYMMDD-乱数3桁` / 選手ID `p-XXXX` / 登録日 /
  `priceHistory: []`。価格を入力した場合のみ `source: "手動"`・確認日は当日

判断メモ（仕様に明記がなかったもの）:

- 書き込みのたびに `exportedAt` を書いた時刻へ更新する（ファイルの最終更新が読み取れるように）
- 層と収納先の初期値（**段階2-Bで変更**。下の「段階2-Bで入ったもの」参照）

### フェーズ3で入ったもの

カード詳細の下に操作を3つ置いた。いずれも1操作＝1コミット。

- **編集** — 取り込みと同じフォームを使い回す（`js/cardform.js`）。項目の並びも検証も1か所で済む
  - カードは全項目。`priceHistory` は cowork の担当なので持ち越し、`addedAt` と カードIDも変えない
  - 価格は、値を変えたときだけ 手動・当日 で書き換える。据え置きなら cowork が入れた
    情報源・確認日を消さない。prices.json が当たっているカードでは「表示は cowork の値が優先」と注記する
  - シリアルの再確認は、**値を変えたときだけ**求める（登録時に一度確認しているため）
  - 選手は **表記（name / nameEn / nationality / notes）だけ**直せる。
    currentTeam / status / infoUpdatedAt は cowork 所有なので触らない（スキーマ仕様 §6）
  - 紐づけ先の選手も選び直せる（検索から既存へ、または新規作成）。取り込みで選手を間違えても直せる
- **価格ウォッチ切替** — 詳細からワンタップ。コミットは `iphone: edit c-xxxx`
- **倉庫へ移動（登録解除）** — 確認ダイアログのうえでカードを削除。コミットは `iphone: delete c-xxxx`。
  選手レコードは残す（スキーマ仕様 §5: 再昇格時に選手IDを維持できる）

判断メモ（仕様に明記がなかったもの）:

- 編集時のシリアル再確認は「値を変えたときだけ」。毎回チェックを求めると編集のたびに手数が増えるため
- 選手の表記編集は取り込みフォームでも同じように効く（判定のカナ表記ミスをその場で直せる）。
  実際に値が変わったときだけ players を書き換える

### フェーズ4で入ったもの

- **エクスポート**（`js/export.js`）— 設定画面から。オーバーレイを畳み込んだ
  マージ済み collection.json（v1.2形式）を1ファイルで書き出す。体裁はリポジトリの
  collection.json と同じなので、差分を取れば何が違うか読める。
  iPhoneでは共有シート（「ファイルに保存」でiCloud/本体へ）、
  対応していない環境ではダウンロードになる。`exportedAt` は書き出した時刻に更新する
- **オフライン閲覧**（`js/cache.js`）— 取得できた3ファイルを localStorage に取り置き、
  起動時は通信を待たずにまずそれを描画する。圏外でも一覧・詳細・エクスポートができる。
  **書き込みは「このセッションでGETできた」ときだけ**許し、それ以外は取り込み・編集・
  登録解除・ウォッチ切替のボタンを止めて理由を出す（保存同期方式仕様§4）。
  オンラインに戻ると自動で取り直す
- **Service Worker** — インストール時にアプリ殻を一式先読みする（実行時キャッシュだけだと
  初回起動の直後に圏外へ入ったとき取り損ねが出る）。取得は従来どおりネットワーク優先。
  画面遷移がオフラインで失敗したときは入口のHTMLに落とす
- **manifest** — `id` を追加（インストール済みアプリの同一性の判定に使われる）

判断メモ（仕様に明記がなかったもの）:

- ファイル名は `collection-YYYY-MM-DD.json`。月1回のバックアップを並べたときに日付で並ぶ
- キャッシュには owner / repo も一緒に持ち、設定を別リポジトリに変えたら読まない
- 「設定を消去」はPATと一緒にキャッシュも消す（端末を手放す場面で所持リストの写しを残さない）
- 保存に失敗した場合（容量不足など）は取得状況にその旨を出す。黙って落とすと
  オフラインで開けない理由が分からなくなる

### 所持カードの詳細から狙い選手を出し入れできるようにした（2026-11-09）

★画面の検索から選ぶしかなかったが、持っているカードを見ているときに「これの別パラレルが
欲しい」と思うことが多いので、詳細の操作欄に「狙いに追加 / 狙いから外す」を足した。

- 書き込みは★画面と同じ `addTarget` / `removeTarget`（`refdata.js`）と
  `commitTargets`（`iphone: targets add|remove {nameEn}`）。経路を2つ作らない
- 登録する中身は `targetableFromRow`（`refdata.js`）が作る。**照合キーは `nameEn`** なので、
  選手データが無い行・nameEn が空の行は登録できない（ボタンを隠す）。カナが無ければ
  nameEn を名前に使う（空の `name` で登録しない）
- 同じ選手の2枚目以降のカードを開くと「狙いから外す」になる（nameEn で照合するので
  カード単位ではなく選手単位）
- 外すときだけ確認を出す（★画面と同じ）。メモは空で入る（付けたいときは★画面で足す）
- `commitTargets` が `library.refresh()` を呼ぶので、GBビューの「狙い」バッジも
  その場で増減する

### GBビューに「狙い選手がどのスポットから出るか」を出した（2026-11-07）

GBを買うときの判断材料。狙い選手（`targets.json`）ごとに、どのスポットに入るか・
いくらか・そこから何が出るか（オート / レリック / インサート / ベース）を出す。
スポット側にも「狙い」バッジを付けて、スポットを眺めているときに気づけるようにした。

- **スポットの決め方は2段階**（`gb.js` の `targetsInBreak`）。まず `spots[].playersEn` の
  名指し。無ければ**カードに印字されたチーム**（チェックリストの `cards[].team`）で引く。
  現所属ではなくカードのチームを見る — 同じ選手でも製品によって所属が違うため
  （ガルナチョは Merlin 2024-25 では Man United、Museum 2025-26 では Chelsea）
- 1チームが複数スポットに分かれるブレイク（Stadium Club の Arsenal は4スポット）で
  名指しが無いときは、どれに入るか決められない。候補を全部出して `ambiguous` を立て、
  画面には「（候補）」と但し書きを出す
- **分母は幅で出す**（`/250〜/1`）。どのラダーにも 1/1 があるので最少だけでは差が出ない
- **台帳・players_info の現所属は使わない**（2026-11-07 に外した）。最初は「チェックリストに
  その選手のカードが無ければ現所属で拾う」保険を入れていたが、2024-25 Merlin の
  Aston Villa スポットに鈴木彩艶とマンザンビが出るように見える誤りになった。
  2人の現所属（アストン・ヴィラ）は正しく、**現所属がその製品の所属ではない**のが問題
  （2024-25 当時は鈴木はパルマ、マンザンビはフライブルク）。
  **証拠（名指し or チェックリストのカード）が無いなら出さない**
- 出なかった狙い選手については、言い切れるかどうかを最後の1行で書く。チェックリストが
  無い → 名指しだけで見ている / `cardsCoverage` が `full` でない → 「出ないとは言い切れません」/
  `full` → 「この製品にはありません」

### 新規登録から収納先の選択を外した（2026-11-07）

スキーマ仕様 §5-1 は「storage は magnetic / toploader の2択」だったが、毎回選ぶ手数に
見合わないのでやめた。**新規登録（取り込み・チェックリスト登録）は常に金庫・トップローダー**で、
マグネットローダーに入れたカードは保存後に詳細 →「編集する」で直す。

- `cardform.js` は `setMode` で収納先の欄ごと隠し、`fill` / `read` は編集以外では
  `toploader` を返す（層と同じ扱い）。編集では3種とも選べる — 既存のバインダー348枚と
  マグネット67枚を直せなくなるし、§5-2 の「ギャラリー→金庫」の昇格にも要る
- 取り込みの下書きから「シリアル・サイン・パッチ付きならマグネット」の推測を外した
- 絞り込みチップの「収納」と詳細の「収納先」はそのまま（既存データの区別は残る）
- `docs/` の §5-1・§7-1・§8-2・§10-3 も書き換えた。**claude.ai の正本にも反映が要る**

### 段階4（統合確認）で直したもの

仕様4点（JSONスキーマ / 保存同期方式 / 写真判定運用 / 引き継ぎ）を通して読み、実装と突き合わせた。

- **productKey の規則が仕様どうしで矛盾していた。** 写真判定運用仕様 §3-2 は
  「`{season}-{maker}-{series}` をそのままスラグ化」と書いていたが、それだと
  JSONスキーマ仕様 §9-3 のサンプル（`2025-26-topps-chrome-uefa-club-competitions`）にならず

- **`denominator: "unknown"`**（写真判定 §3-3）を `checklist_import.py` が弾いていた →

- **variation のオートコンプリート**（同 §7-1「製品のチェックリストを第一候補、既存登録値を補助候補」）
  が未実装だった → 取り込みフォームを開いたときに、判定の maker/series/season から productKey を
  作り、該当するチェックリストがあればそのパラレル名を先頭に並べる

### 段階3で入ったもの

ヘッダーの「▤」から。製品（チェックリスト）とGBを並べ、中身は**開いたときに個別GET**する
（保存同期方式仕様 §4。大型製品を起動ごとに引かないため）。取れた1件だけ取り置くので、
直前に見た製品は圏外でも開ける。

- **productKey**（`js/checklist.js`）— チェックリストと台帳をつなぐ鍵で、ファイル名そのもの。
  仕様に生成規則が無かったので `{season}-{maker}-{series}` をスラグ化し、
  **series が maker で始まるときは maker を重ねない**ことにした（§9-3 のサンプルを再現する形）。
  同じ規則を `dev/_common.py` にも置いてある — **片方だけ直すと所持照合が静かに外れる**
- **所持照合**（同 §10-2）— パラレルごとに 所持 / 別パラレル所持 / 候補あり / 未所持 を出し、
  行のまとめはその中でいちばん強いものにする。cardNo は大文字小文字と空白を無視して突き合わせ、
  同じ番号で nameEn が違えば警告を出す（§10-1）
- **チェックリスト閲覧**（写真判定運用仕様 §7-3）— パラレル一覧・出典・網羅度を出し、
  「パラレル一覧をコピー」で `variations[]` だけを JSON でクリップボードへ（判定チャットの冒頭用）
- **チェックリスト登録**（登録経路B。同 §8）— 行とパラレルを選ぶと、製品・カード番号・
  パラレル・チーム・特徴・選手候補が埋まった状態でフォームが開く。入れるのは
  serial（＋実物と一致チェック）/ storage / priceWatch / notes / gbRef だけ。
  保存時に `sourceChecklist` を記録する（§10-3）。保存経路は写真判定と同じ（`iphone: add ...`）
- **GBビュー**（§9-4）— スポットごとに価格・チーム・選手と、`gbRef` が一致するカードを出す。
  **期待値や確率は持たない**（FCGB のレポートが正。参照パスだけ出す）
- **`dev/checklist_import.py`** — 下書きJSONを正規化して検証し、`checklists/{productKey}.json` に書く。
  チーム名は teams.json の正式名に寄せ、`parallels` が `variations[]` にあるか、cardNo が重複しないか、
  productKey がファイル名と一致するかを見る。1件でも落ちたら**何も書かずに中止**する。
  `--check` で既存ファイルをまとめて検証できる
- **`dev/gb_export.py`** — FCGB の breaks/spots/checklist_entries.csv から `gb/{breakId}.json` を作る。
  スポット名（「Barcelona - Dro/Fernandez/Junyent」）からチームを teams.json で解決し、
  選手名は card_name から取る

判断メモ（仕様に明記がなかったもの）:

- **FCGB の `card_id` はカード番号ではない。** `BAR_DRO` のような評価用の内部IDなので、
  ここからカード番号を作ってはいけない（作ると所持照合が静かに外れる）。
  `gb_export.py` は番号を作らず、`card_name` の末尾に `(CTA-SGR)` と入っている場合だけ本物として扱う
- gb/ は §9-4 の前提どおりチェックリストが先。無いときは中止し、
  どうしても先に作るなら `--allow-missing-checklist` を付ける（所持照合は使えないと警告する）
- `gbRef` はブレイク単位なので、**スポットへの割り当ては推測**（プリント時チーム・現所属・選手名）。
  どのスポットにも結び付かなかったカードは「結び付かなかった」として必ず出す
- チェックリスト閲覧の区分チップは、選択が空なら全部出す（一覧のチップと同じ考え方）
- ヘッダーのボタンが5つになったので、狭い画面では詰め、タイトルを「トレカリスト」に短くした

### 推定価格の表示（スキーマ仕様 §9-7）

prices.json のエントリは大半が**実測を持たず推定だけ**（2026-11-04 時点で127件中116件）。

- **マージ**（`js/merge.js`）— `price` は**実測（current が数値）のときだけ**差し替える。
  以前は推定だけのエントリでも `{current: null, checkedAt: null, source: null}` で上書きしていて、
  台帳に手入力した価格を消していた。`estimate` は別フィールドでカードに載せる
- **表示** — 実測があれば実測。無ければ「推定 ¥84,000」。信頼度が**低**のときは値を出さず
  「推定 ¥150〜¥2,900」と幅だけ出す（§9-7）。推定は実測より一段弱い見た目にする
- **詳細** — 「推定価格」の節で 推定 / 信頼度 / 出し方（exact・model・fallback）/ 推定日 /
  根拠（basis）を出し、実測があるときは「一覧には実測を出しています」と添える
- **並び替え** — 「現在の価格」は実測が無ければ推定の `value` で並べる。一覧の件数行に
  「うちn枚は推定で並べています」と出す（幅のまま並べる方法が無いので、低信頼も value を使う）
- **エクスポート** — `estimate` は collection.json のカードには無い項目なので書き出さない

### 段階2-Bで入ったもの

参照データ（スキーマ仕様 §9）を読むようになり、一覧の探し方とテーマが増えた。

- **参照データの取得**（`js/github.js`）— 起動時に `teams.json` / `targets.json` を個別GETし、
  `checklists/` / `gb/` はファイル名の一覧だけ取る（中身は選ぶときに個別GET。段階3）。
  **404は「未作成＝空」として扱い、エラーにしない**。取得状況の画面にも「未作成」と出る。
  参照データも localStorage に取り置くので、オフラインでも絞り込みとテーマが効く
- **年齢**（`js/query.js`）— `players_info.json` の `birthDate` から表示時に算出する
  （スキーマ仕様 §1「年齢はデータに持たない」）。一覧ではカード表記の隣、詳細では選手欄に出る。
  ソート項目に「年齢」が増えて9項目。未設定は昇順・降順どちらでも末尾
- **在籍履歴**（`js/merge.js`）— `careerHistory` は collection.json の players に持たない項目なので、
  マージ結果には混ぜず `career`（選手ID → 履歴）で別に返す。**エクスポートにも出ない**。
  詳細では新しい順に並べ、ローン移籍は「（ローン）」を付ける
- **フリーワード検索**（`js/query.js`）— 対象はスキーマ仕様 §1 のとおり選手・カードの13項目。
  複数語はAND、ヒット単位はカード。NFKC・大文字小文字・かな/カナを吸収する。
  **チーム名は `teams.json` の `aliases` でも当たる**（「Spurs」で Tottenham Hotspur のカードが出る）
- **チップ絞り込み**（`js/query.js` の `CHIP_GROUPS` ＋ `js/chips.js`）— 層 / 収納 / 特徴 /
  シリアル / 価格ウォッチ / チーム。同一区分内はOR、区分をまたぐとAND。選択が空の区分は条件なし。
  **既定はギャラリー非表示**（層チップ「金庫」だけが押された状態。スキーマ仕様 §5-1）
- **チームテーマ**（`js/theme.js`）— チームを1つだけ選んでいる間、背景とヘッダーがそのチームの色になる。
  壁紙（`themes/`）があればそれ、無ければ `colors` のグラデーション。
  カードや入力欄は不透明のままにして、本文の読みやすさは動かさない
- **狙い選手**（`js/targets.js`）— ヘッダーの「★」から。追加・削除と所持状況の表示。
  `targets.json` は **PWAが書き込む2つ目のファイル**で、未作成のときは sha なしでPUTして作る。
  409の自動リトライは collection.json と同じ仕組み（`commitFile`）
- **取り込みフォームの v1.4 対応**（写真判定運用仕様 §7-1）— 新規登録は層を選ばせず常に金庫、
  収納はマグネット/トップローダーの2択、`priceWatch` の既定はON、`gbRef` を選べる。
  編集では既存データのためにギャラリー・バインダーも選べる（§5-2の昇格ができるように）

判断メモ（仕様に明記がなかったもの）:

- **チームチップは「所持カードに出てくるチーム」だけを、枚数の多い順に上位8件**出す。
  `teams.json` は159チームあり、所持カードに出るものだけでも100件を超えるので、
  全部チップで並べるとiPhoneでは探せない。それ以外は「チームを選ぶ」の検索シートから選ぶ
  （正式名・日本語名・別名のどれでも絞れる）。選択中のチームは下位でもチップに残す
- チームの照合モード（プリント時 / 現所属 / 在籍経験）を変えると母集団が変わるので、
  **モードを切り替えたらチームの選択は外す**（残すと0件になりやすい）
- チップの枚数は「チーム以外の条件を当てたあと」の行で数える
  （いま見ている条件の中でどのチームが何枚あるか、が分かるように）
- 収納先の初期値は、シリアル・サイン・パッチ付きなら マグネットローダー、それ以外はトップローダー
- 壁紙が置かれていないときは黙って配色グラデーションに落とす（`Image` で先に読めるか試す）。
  当面の3枚（Urawa Red Diamonds / FC Barcelona / Aston Villa）は `themes/` に配置済みで、
  それ以外の156チームは配色グラデーションになる
- 壁紙のパスは `document.baseURI` 基準の絶対URLにしてからCSS変数へ渡す。
  CSSカスタムプロパティの `url()` は**スタイルシートの場所**を基準に解決されるので、
  `themes/...` をそのまま渡すと `css/themes/...` を取りにいって外す
- 壁紙の上に敷くスクリムは、上を薄く・下を濃くする。カード・入力欄は不透明なので、
  守るのは背景に直接乗る文字（一覧の件数・絞り込みの注記）だけ。テーマ中はその2つを本文色に上げる
- `gbRef` は `gb/` が空なら選べない（注記を出す）。台帳に入っている break_id が
  `gb/` に無い場合は「（gb/ に未登録）」として選択肢に足す — 編集で保存しただけで値が消えないように

## PAT について

設定画面で入力し、localStorage に保存する（保存同期方式仕様 §4）。

- Fine-grained PAT を、対象リポジトリ **`soccer-cards-data` のみ**に限定して発行する
- 権限は **Contents: Read and write**
- トークンは端末に平文で保存されるため、共用端末では使わない
