# soccer-cards-app

サッカートレカ所持リスト PWA。iPhone Safari（ホーム画面に追加）で使う前提。
データは private リポジトリ [soccer-cards-data](https://github.com/tetsuf0605-rgb/soccer-cards-data) に置き、
GitHub Contents API で読み書きする。仕様の正はそちらの `docs/` にある4点。

## 技術方針

ビルドなしの静的構成。HTML + CSS + JavaScript（ES modules）のみで、
フレームワーク・npm依存・ビルドステップは使わない（push＝デプロイを維持するため）。

## ローカルでの動作確認

ES modules と Service Worker は `file://` では動かないので、必ずHTTPで配信する。

```sh
cd soccer-cards-app
python -m http.server 8765
```

- アプリ: <http://localhost:8765/>
- セルフテスト: <http://localhost:8765/dev/selftest.html>

## 構成

```
index.html                 画面の骨格（一覧 / 詳細 / 取り込み・編集 / 設定）
css/style.css              モバイルファーストのスタイル
js/app.js                  エントリ。画面の配線と読み込みフロー
js/config.js               接続設定（PAT / owner / repo）の localStorage 入出力
js/github.js               Contents API クライアント（読み3ファイル・書きは collection.json のみ）
js/base64.js               UTF-8 経由の base64 変換
js/serialize.js            collection.json の書き出し（仕様§3の体裁を保つ）
js/merge.js                オーバーレイマージ（保存同期方式仕様 §3）
js/query.js                絞り込みと8項目ソート（スキーマ仕様 §1）
js/ingest.js               判定JSONの読み取り・選手マッチ・採番・台帳の更新（純粋関数）
js/cardform.js             取り込みと編集で共用するカードフォーム（UI部品）
js/ingestform.js           取り込みのフロー（写真判定運用仕様 §5）
js/editform.js             編集のフロー
js/render.js               データ → DOM（ビュー層）
js/confirm.js              画面内の確認パネル（window.confirm の代わり）
manifest.webmanifest       PWAマニフェスト（パスはすべて相対。GitHub Pagesのサブパス配信のため）
sw.js                      Service Worker（ネットワーク優先の最小構成）
icons/                     アイコン一式
dev/                       開発用。アプリ本体からは読み込まれない
```

### 設計上の約束ごと

- **書き込むのは `collection.json` だけ。** `prices.json` / `players_info.json` は
  cowork 所有のため、書き込む関数を作らない（保存同期方式仕様 §2・§3）
- **base64変換は必ずUTF-8バイト列を経由する。** 選手名や備考に日本語が入るため
  `btoa(JSON.stringify(...))` は使えない（`js/base64.js`）
- **Service Workerは同一オリジンのみ扱う。** GitHub APIのレスポンスはSWを通さない
  ＝PATで認証した個人データをキャッシュに残さない
- **`window.confirm` / `alert` は使わない**（`js/confirm.js` の画面内パネルで代用）。
  ホーム画面に追加したPWAやアプリ内ブラウザではダイアログが出ずに即 false が返ることがあり、
  「削除ボタンが効かない」「取り込みを中止できない」という詰まり方をする
- **Service Workerはネットワーク優先。** 古いアプリ殻を掴んで更新が届かなくなる事故を避ける
- **書き出しの体裁はスキーマ仕様§3のサンプルに合わせる**（`js/serialize.js`）。
  コミット履歴が台帳を兼ねるので、1枚追加した差分がそのカードの1ブロックで収まる形にする

## セルフテスト

PATなしで検証できる範囲を `dev/selftest.html` にまとめている（GitHubへの実通信はしない）。
Contents API のレスポンスは `dev/fixtures.js` で差し替える。

`dev/fixtures.js` はスキーマ仕様 §3 のサンプル（架空の2枚）を Python で base64 化したもの。
アプリ側の符号器とは独立しているので、UTF-8経路の突き合わせに使える。再生成は:

```sh
python dev/gen_fixtures.py            # 既定で ../soccer-cards-data を読む
```

> **このリポジトリは public。実際の所持カードデータを `dev/` に焼き込まないこと。**
> `gen_fixtures.py` はサンプル以外を検出したら中止する。

### フェーズ1で入ったもの

- **オーバーレイマージ**（`js/merge.js`）— エントリがあればオーバーレイ優先。
  フィールド単位で存在を見るので、部分的なオーバーレイでも台帳側を巻き込まない。
  結果はスキーマv1.2の形を保つ（フェーズ4のエクスポートでそのまま使える）
- **8項目ソート**（`js/query.js`）— スキーマ仕様 §1 の対応表どおり。
  選手側のキーは playerId で結合して引く。値なしは昇順・降順どちらでも末尾。
  引退状況は文字列順ではなく 現役 → 引退 → 不明
- **検索** — 選手名（name / nameEn）。NFKCで全角を吸収し、
  ひらがなをカタカナに寄せる（かな入力で「べりんがむ」→「ベリンガム」に当たる）
- **詳細ビュー** — 全フィールドと価格履歴。オーバーレイ由来の値には出所を明記する

### フェーズ2で入ったもの

右上の「＋」から。判定JSONを貼り付け → 1枚ずつ確認 → 1枚ずつ保存（1枚＝1コミット）。

- **取り込みの読み取り**（`js/ingest.js`）— 写真判定運用仕様§4のJSON。単体・複数どちらも
  `items` で受ける。```json のコードブロックごと貼っても読める
- **選手マッチ** — nameEn（無ければカナ名）で既存選手を検索。大文字小文字・空白・
  アクセント記号・区切り記号のゆらぎを吸収する。完全一致が1人だけならそれを既定選択、
  それ以外は「新規作成」を既定にして、判定結果を初期値にした入力欄を開く。
  候補に出ない選手は検索欄から選べる
- **表記寄せ** — メーカー / シリーズ / バリエーション / プリント時チーム / シーズン /
  バインダー名 / 国籍を、既存の登録値から datalist で提示する
- **needsCheck の強調** — 判定側が自信なしと言った項目を色つきで囲み「要確認」を付ける
- **シリアルの最終確認** — 値が入っているときは「実物と一致」チェックなしでは保存できない
  （空欄のときは不要。まとめ撮りのギャラリー層は serial が null で返る前提のため）
- **保存**（`js/github.js`）— collection.json だけをPUT。409（sha不一致）なら
  再GET → 同じ変更を当て直し → 再PUT を自動で1回。IDの採番は当て直しの中でやり直すので、
  他端末が先に登録していてもIDは衝突しない
- **自動で付ける値** — カードID `c-YYYYMMDD-乱数3桁` / 選手ID `p-XXXX` / 登録日 /
  `priceHistory: []`。価格を入力した場合のみ `source: "手動"`・確認日は当日

判断メモ（仕様に明記がなかったもの）:

- 書き込みのたびに `exportedAt` を書いた時刻へ更新する（ファイルの最終更新が読み取れるように）
- 層と収納先の初期値は、シリアル・サイン・パッチがあれば 金庫＋トップローダー、
  それ以外は ギャラリー＋バインダー（スキーマ仕様§4の「原則」に合わせた下書き。変更可）
- バインダー名は直前に保存した値を覚えて次の1枚の初期値にする（連続登録の打鍵を減らす）

### フェーズ3で入ったもの

カード詳細の下に操作を3つ置いた。いずれも1操作＝1コミット。

- **編集** — 取り込みと同じフォームを使い回す（`js/cardform.js`）。項目の並びも検証も1か所で済む
  - カードは全項目。`priceHistory` は cowork の担当なので持ち越し、`addedAt` と カードIDも変えない
  - 価格は、値を変えたときだけ 手動・当日 で書き換える。据え置きなら cowork が入れた
    情報源・確認日を消さない。prices.json が当たっているカードでは「表示は cowork の値が優先」と注記する
  - シリアルの再確認は、**値を変えたときだけ**求める（登録時に一度確認しているため）
  - 選手は **表記（name / nameEn / nationality / notes）だけ**直せる。
    currentTeam / status / infoUpdatedAt は cowork 所有なので触らない（スキーマ仕様 §6）
  - 紐づけ先の選手も選び直せる（検索から既存へ、または新規作成）。取り込みで選手を間違えても直せる
- **価格ウォッチ切替** — 詳細からワンタップ。コミットは `iphone: edit c-xxxx`
- **倉庫へ移動（登録解除）** — 確認ダイアログのうえでカードを削除。コミットは `iphone: delete c-xxxx`。
  選手レコードは残す（スキーマ仕様 §5: 再昇格時に選手IDを維持できる）

判断メモ（仕様に明記がなかったもの）:

- 編集時のシリアル再確認は「値を変えたときだけ」。毎回チェックを求めると編集のたびに手数が増えるため
- 選手の表記編集は取り込みフォームでも同じように効く（判定のカナ表記ミスをその場で直せる）。
  実際に値が変わったときだけ players を書き換える

## PAT について

設定画面で入力し、localStorage に保存する（保存同期方式仕様 §4）。

- Fine-grained PAT を、対象リポジトリ **`soccer-cards-data` のみ**に限定して発行する
- 権限は **Contents: Read and write**
- トークンは端末に平文で保存されるため、共用端末では使わない
